# 前半・後半のナイン選択 設計

## 目的

ラウンドごとに、回る2つの9ホールとその順序を指定できるようにする。あわせてコース側の
パー情報からニアピン（パー3）・ドラコン（パー5以上）を自動で埋め、毎ラウンドの手作業を無くす。

現状はホール1〜18が固定で、スタートは常に1番。実際には次のことが起きている。

- インスタートの日がある（IN が前半になる）
- 27・36・45ホールの施設があり、どの9ホールを回ったかで配置が変わる
  （例: 川越グリーンクロス = 南・中・北、太平洋クラブ軽井沢リゾート = 浅間OUT/IN・白樺OUT/IN、
   ニドムクラシックコース = ニスパOUT/IN・アシリ・ピリカ・カムイ）
- 施設をまたいだ組み合わせで回ることもある（浅間OUT + 白樺IN）

## 前提

`courses` / `courseAliases` は BackOffice の `tools/golf-course-par` が生成し、
Firebase に投入済み（52コース / エイリアス69件）。アプリからは**読み取り専用**。

```
courses/<キー>/
  displayName: "太平洋クラブ軽井沢リゾート"
  nines: { "浅間OUT": [4,4,3,4,5,4,4,5,3], "浅間IN": [...], "白樺OUT": [...], "白樺IN": [...] }
  source / verified / citations / updatedAt

courseAliases/<生の表記>: "<キー>"
```

セキュリティルールは `".read": "auth != null", ".write": false`。アプリからは書けない。

## データ構造

ラウンドの `cfg` に2フィールド追加する。既存フィールドは変更しない。

```javascript
cfg: {
  courseName: "太平洋クラブ軽井沢リゾート",
  courseKey:  "太平洋クラブ軽井沢リゾート",   // courses のキー
  holes:      ["浅間OUT", "白樺IN"],         // 前半・後半（この順）
  ...既存（date, cnt, names, avs, pts, scoringMode, nikaiNearpin, nikaiDracon）
}
```

`nph` / `dch` は**従来どおり位置1〜18のマップで保存する**。ナインを選んだ時点で算出して
埋め、その後は従来のボタンで手動変更できる。手動変更は `nph`/`dch` にそのまま入るため、
保存・リアルタイム同期・集計は無改造で動く。

**`holes` を持たないラウンドは旧形式**と判定し、従来の 1〜18 表示にフォールバックする。
既存30ラウンドのデータ移行は行わない。過去のスコアは今までどおり見られる。

## ホール番号のラベル

位置（1〜18）から表示ラベルを作る純関数を1つ足す。

```
holeLabel(pos, holes)   pos: 1..18

  holes なし（旧形式）      → "1" ... "18"
  ["OUT","IN"]              → "OUT 1".."OUT 9" / "IN 10".."IN 18"
  ["IN","OUT"]              → "IN 10".."IN 18" / "OUT 1".."OUT 9"
  ["東コース","西コース"]    → "東コース 1".."東コース 9" / "西コース 1".."西コース 9"
  ["浅間OUT","白樺IN"]      → "浅間OUT 1".."浅間OUT 9" / "白樺IN 1".."白樺IN 9"
```

**`OUT` と `IN` のときだけ IN を 10〜18 とする。** それ以外のナイン名は各ナインで 1〜9。
27ホール以上の施設は実際のスコアカードが各ナイン 1〜9 で振られているため。
インスタートでも IN は 10〜18 のままとし、コースの案内板と一致させる。

判定は「ナイン名が `OUT` または `IN`（大小無視）であること」。`浅間OUT` は該当しない。

ラベルは `cfg.holes`（ラウンドに保存済み）だけから作り、描画時に `courses` を参照しない。
コース側のナイン名が後から変わっても、過去ラウンドの表示は当時のまま保たれる。
`courses` を引くのはナインを選ぶ瞬間だけ。

## ニアピン・ドラコンの導出

前半・後半のパー配列を連結して18ホール分を作り、パー3を `nph`、パー5以上を `dch` に入れる。
パー6はドラコン扱い（上里カントリークラブ、軽井沢72に実在する）。

自動適用後も従来のボタンで手動変更できる。パー3でもニアピンをやらない日や、
ローカルルールに対応するため。

## 変更する箇所

| 箇所 | 変更 |
|---|---|
| `rSet()` (1139行) | コース名の下にナイン選択を追加。`courseAliases`→`courses` を引き、前半・後半を順に選ぶ |
| `holeLabel()` | 新規。上記のラベル生成 |
| `rInput()` (1111行) | ホール番号の表示をラベルに差し替え |
| `rList()` (1112行) | 表の行見出しをラベルに。OUT/IN の集計見出しを前半・後半のナイン名に |
| `raw()` (1015行) | 変更なし。ニアピン2回戦の前後半判定 `h<=9` は位置基準で正しい |
| `tOut()` / `tIn()` (1017-1018行) | **中身は変更なし。** 前半9・後半9の合計という意味は変わらない。表示名のみ変える |

`tOut`/`tIn` の実装を変えないのが要点。位置基準の集計は正しいままで、
名前が指すものだけがナイン名に変わる。

## エラー処理

| 事象 | 挙動 |
|---|---|
| コース名が `courseAliases` に無い | ナイン選択を出さない。従来どおり手動設定 |
| `courses` の読み取りに失敗 | 同上。エラーダイアログは出さない |
| ナインが2つだけの施設 | 前半・後半の既定を出すが、順序は変更できる |
| ナインが3つ以上 | 前半・後半とも選択必須。既定は置かない |
| 前半と後半に同じナインを選んだ | 選択させない（同じ9ホールを2周する運用は想定しない） |

## テスト

このアプリにテストの仕組みは無く、`index.html` は単一ファイルの静的ページで
GitHub Pages で配信されている。モジュール分割は配信方法に影響するため行わない。

**動作確認は目視で行う。** 確認項目:

- 旧形式のラウンド（`holes` なし）が従来どおり 1〜18 で表示される
- `["OUT","IN"]` で OUT 1-9 / IN 10-18
- `["IN","OUT"]` で IN 10-18 が前半、OUT 1-9 が後半に来る
- 27ホール施設で各ナイン 1〜9 表示
- ナイン選択でニアピン・ドラコンが自動で埋まる
- 自動適用後に手でトグルでき、その値が保存される
- コース未登録時にナイン選択が出ず、従来どおり手動設定できる

## やらないこと

- 既存30ラウンドへのナイン情報の付与（移行しない）
- 同じナインを2周する運用への対応
- コースのクローズ情報の保持（開閉は頻繁に変わり、古い情報が固定化するため）
- `courses` のアプリからの編集（セキュリティルールで書き込み禁止）
